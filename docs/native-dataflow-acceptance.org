* Invocation-scoped policy body preparation

The complete catalog contains 1000 policy normalization observations across
221 revisions, with 335 distinct sources within their individual manifest
invocations. A JSON-keyed diagnostic reused 665 results but still paid for
=Policy.to_json()= on every observation. In pinned Cedar SDK 4.12.0, that operation
converts lossless text to EST by parsing the text again; it is not a cheap AST
projection. See the [[https://docs.rs/cedar-policy/4.12.0/src/cedar_policy/api.rs.html][pinned SDK source]] and the
[[https://docs.rs/cedar-policy/4.12.0/cedar_policy/struct.Policy.html#method.to_cedar][original-text API contract]].

The private =ParsedTextPolicies= owner can only be created by the text parser.
Its policy iterator therefore supplies static policies with their complete
original text, rather than a lossy display of JSON/PST/linked objects. A
=PreparedPolicyBodies= owner keys pure canonical bodies by those exact source
strings before entering =to_json()=. Every miss runs the original normalizer;
only successful results are retained. Different source formatting conservatively
misses even when the normalized result agrees. Policy IDs, revision labels,
credentials, contexts and observed decisions do not establish identity.

The owner belongs to one manifest invocation and is dropped on return. It is
not a global cache or an authorization cache. Each revision still loads its
actual JSON source, independently parses its complete rendered text, compares
body multiplicities and retains both actual authorizers. Every request and both
authorizations still execute. Schema validation/error ordering and conflicting
revision-output refusal remain unchanged. The independent original-workflow
oracle disables body preparation sharing as well as entity reuse.

The full emitted-catalog Rust test checks 335 actual normalizations, 665 reuses,
a maximum owner inventory of 21, and all 2560 authorizations. Smaller controls
cover changed bodies under the same policy ID, source formatting, exact uncached
normalizer equality and invocation retirement. The inventory of 21 is a measured
fixed-corpus maximum, not a heap/RSS or arbitrary-input bound.

Direct Cargo, Justfile and CI now use the same workspace-owned =rust/target=
through =.cargo/config.toml=. The Justfile-only target environment setting is
removed; compiler profiles, job defaults and limits are unchanged. The package
boundary audit uses actual Cargo package names from flattened package records,
so a checkout path containing =cedar-policy=, =mrr-data= or =p256= cannot masquerade
as a dependency. Real direct/transitive prohibited packages remain refused.
