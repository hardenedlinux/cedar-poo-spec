The first Cedar CI run at =a0dc449= passed Lean, Rust and authorization-delta,
but the new cold native catalog link exposed an existing artifact-owner violation.

=lp_CedarPooSpec_CedarPooSpec_...= names exported by the cached native objects.
A warm previously linked local executable had masked the cold-link failure.

The local negative control uses the real AttestedDataAccess module: canonical
Lake output hash =8473d767db67d22a79d96a3a65654789ce33522b09d0f6bc529558b3db5e7711=
changes to =0f09b2f99e9a447d3d8b08bae0b5fd383bb367a8c414b80d0b3baac507ab03c6=

All such recipes now ask Lake to build their modules. Standalone checks retain
their exact 120-second, 2048-MiB, 10000000-tick bounds and do not publish artifacts.
The native gate executes governance, procurement and delegation checks between
checksums of the three actual .olean files; any mutation fails before linking.
A fresh project-only lib/ir/bin build rechecks the cold native path. Frozen
performance binaries and raw evidence are retained outside those generated paths.
The original repair used numbered cache namespaces, and an intermediate restore
prefix still selected the contaminated artifacts. The current cache uses
content-derived compatibility instead: the actual Lean/Lake/bundled C compiler
identities (including target), platform, pinned dependency/configuration files,
and artifact-writing recipes determine a SHA-256 identity. Neither a manual
version number nor the whole CI workflow acts as an invalidation switch.

The pinned =lean-action= also enables a whole-=.lake= GitHub restore/save by
default, independently of =auto-config/build/test/lint=. The first content-key

The workflow reports the requested identity and exact-hit state; a restored

artifact mutation, cold-link and replay gates still determine acceptance.

The next performance unit is the complete catalog lifecycle across all 51
entries, rather than another family-specific revision benchmark:

1. Attribute native module initialization, manifest production and serialization
   separately while preserving the ordinary complete-process control and exact
   wire bytes. The new object algorithm's savings are not visible as a producer
   CPU improvement in either cohort.
2. Audit invocation-scoped immutable policy/schema preparation and canonical text
   normalization in Rust. Existing measured subphases show preparation, not just
   authorization, remains material. Keep the independent text-side parser,
   compiled/rendered authorizers, strict error ordering and uncached reference.

   source equations, complete support and current dependency ranks. Empty-node
   sharing is already implemented; nonempty graph/index rebuilding remains.
4. Re-run the same full semantic, original-workflow/mutation, fixed native process
   and resource cohort together. Preserve every prior cohort and distinguish
   allocation improvements from whole-process CPU, wall time and RSS outcomes.

No timeout, case-count, workload, admission, axiom or resource guard may be relaxed.
