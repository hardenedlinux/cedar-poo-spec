#+TITLE: Zero Trust Framework API and Application Specialization
#+LANGUAGE: en

* Framework ownership

[[file:../CedarPooSpec/ZeroTrust/README.org][ZeroTrust]] is a generic functional
framework with an optional POO interpretation. The top-level Lean file aggregates
the directory; it contains no Gateway implementation. Read
[[file:rfc/0010-zero-trust.org][RFC 0010]] for research sources, model boundaries,
proofs, counterexamples and concrete Host obligations.

| API | Meaning |
|-----+---------|
| =Requirement Effect View= | Typed function describing one effect/view condition |
| =Framework.required= | Joint authentication, current authorization, freshness, durable consumption, unknown retention, non-revocation and mediation |
| =adapt= / =strengthen= / =withRequirement= | Reuse functions under projections and additional requirements; preserve original implication |
| =Observation= / =atObservation= | Bind actual mutable attributes and a non-reused authoritative generation |
| =MediatedStep= / =Run= / =run_preserves= | Check every declared new effect against its actual state and reuse an existing application's invariant |
| =ZeroTrust.ProfileObject= | Source-bound LeanPoo object inheritance and strengthening Session over original typed requirement functions |

These are framework functions and proof-carrying object profiles, not a new
Cedar evaluator or configuration DSL. Facts, authoritative originals and
linearization are supplied by a trusted application adapter.

* Applications consume the core

[[file:../CedarPooSpec/Gateway/ZeroTrust.lean][Gateway.ZeroTrust]] specializes the
framework through its existing POO publication, actual Cedar admission and
operation/authority consumption. Its Proposal/FinalUse types belong to Gateway.
The original operation is consumed once; ongoing releases use =continuing= with
fresh assessment, original scope and explicit recovered =CommittedPrefix=.

=fromFrameworkObject= requires both an independently required parent Session and
the selected Session. It invokes =composeSessions= and returns a =Composed=
requirement retaining both actual projections. The original type index is the
Gateway publication's framework requirement. The composition theorem preserves
the selected parent's condition and original Gateway Contract. Root-only shape
recognition alone does not preserve extra ancestor requirements under raw POO
overrides. Authenticating the required parent commitment remains a Host duty.

=final_use_satisfies_framework= and
=specialization_preserves_core_and_original= connect Gateway to the functional
core. =continuing_use_preserves_original_consumption= rejects reconsumption
against a current history extending the consumed prefix, including a renewed
Authority. A rolled-back input ledger cannot supply that witness.

[[file:../CedarPooSpec/Authorization/README.org][Authorization]] independently owns
Cedar policy combination and Delta. Gateway composes both frameworks. Pure
records/proofs are duplicable; the native executor still needs a fresh one-use
runtime capability and complete mediation. A final release-completion commit
after queue insertion must not be confused with the original durable-consumption
prerequisite before sending.

* Evidence and limits

=Tests.ZeroTrust.Functional= uses a generic artifact-access fixture with no
Gateway types. =Tests.ZeroTrust.ProfileObject= constructs and reads a real
inherited object through LeanPoo Session. =Tests.ZeroTrust.ImportBoundary=
inspects actual transitive imports and refuses Gateway dependencies.
=Tests.Gateway.ZeroTrust= checks the application adapter and recovery-prefix
counterexamples. All are discovered by the existing Tests aggregate.

Unknown commit/hold blocks use. Currentness alone does not defeat revocation.
An equal attribute value in a later generation cannot revive a stale
observation. Generation non-reuse, authentic reading, atomic persistence,
rollback-resistant recovery and native sender/trace correspondence remain Host
premises, not consequences of naming a predicate currentAtUse.

Earlier isolated alignment snapshots retained their original fixed pins.
The current dependency upgrade is recorded in the integration section below. Historical raw evidence is preserved; inherited Cedar native-decision
axioms remain visible in printed axiom audits. The complete UCON temporal rule
system and deployed NIST compliance are not claimed.

* Research review: authorization, information flow and actual effects

The [[https://csrc.nist.gov/pubs/sp/800/207/final][NIST architecture]], [[https://profsandhu.com/journals/tissec/p351-zhang.pdf][formal UCON model]] and [[https://arxiv.org/abs/2403.04651v2][Cedar paper]]
address different boundaries. Our design deduction is to keep policy change,
current-use admission and the actual mediated effect as separate obligations,
then join their exact inputs. Existing RFC 0010 inventories the implemented
joins; it must not be read as a plan to reimplement them.

| Research question | Current owner/evidence | Remaining obligation |
|-------------------+------------------------+----------------------|
| Does a policy revision expand access in one fixed world? | =AdmissionBinding= + =ExactCoverage=; current-world Delta composition in =Gateway.ZeroTrust= | Executable four-root reports are not kernel coverage certificates. Changed facts need current admission even when policy analysis is reusable. |
| Do revocation and recovery affect every later use? | =UsageControl=, =MediatedStep=, current typed receipts, retained consumption and frontier laws | Join fact updates, revocation, publication, recovery and effect observation under the same application transition refinement. Native simulated publication arbitration alone is not that complete refinement. |
| Can retrieved data change what authority the caller intended? | [[https://arxiv.org/html/2503.18813v2][CaMeL]] separates control/data and tracks provenance; [[https://arxiv.org/html/2609.31039v1][MetaPermit]] separates inference from enforcement | Define which fact sources may establish each attribute. Typed inferred attributes do not establish semantic truth or authorized declassification. No information-flow theorem for the complete application is claimed. |
| Does local acceptance ensure safe future agent behavior? | [[https://arxiv.org/html/2609.15803v1#S4][Delegating Authorization]], Section 4, uses continuation-aware values and discounted MDP assumptions | Neither same-world Cedar no-gain nor a review vote establishes that expected-utility premise. Do not label current SPEC proofs as this paper's sequential guarantee. |

The next integrated simulated acceptance unit should order fact-source mutation,
revocation, registered policy change and final effect admission together. Every
writer must preserve consumption, unresolved exposure and the independent
frontier; source provenance changes invalidate the use decision. Independent
Lean/Rust observations should compare decisions, refusals, effect ordering and
complete post-states, including revocation-before-use and recovery-after-unknown.
This extends existing owners and requires no deployed credentials or new
backend. It remains future work; the preceding theorems and simulations keep
their stated coverage. The PyO3 boundary is a replay consumer, not that authority.


* Current-release coherence: integrated improvement

The improvement joins three distinct boundaries without replacing Cedar:
review the revision in one world; publish a registered release; authorize each
later use against the independently read active release and its current facts.
A same-world implication does not establish either of the latter two steps.
This is a project integration result, not a claim of a new authorization logic.

=ReleaseState.matchesCurrent= compares the actual active root, exact compiled
policy list, enforcing mode and epoch with the current receipt and Gateway
context. =Gateway.ZeroTrust.authorizeCurrent= runs the existing strict typed
admission and retains this binding together with the original Profile
refinement. There is no default release reader. A caller's prepared root alone
cannot establish that its policies are active. A legitimately approved gain
still uses fresh admission; this API does not require every release to be no-gain.

=current_admission_binds_active_release= proves error-free Allow for the actual
active policies at the exact current request/entities. The continuing Delta
composition also binds those active policies to the revision's after-policies,
retains unresolved exposure and rejects reconsumption of the original operation.
The generic binding theorem adds no native-computation axiom; existing Cedar
native-decimal/date axioms remain visible in the Delta theorem's printed audit.

=Tests.Gateway.ZeroTrust= exposes the old counterexample: a valid receipt and
Profile refinement coexist with a different active root. It rejects changes to
root, policies, epoch, observing mode and disabled mode, and retains the existing
changed-fact and original-consumption counterexamples.

[[file:../Productions/Gateway/CurrentUse.lean][Production current-use composition]] uses the actual medical DisclosureProfile
and financial ControllerReleaseProfile, their typed slots and executable POO
Contracts. It constructs four strict-schema Cedar worlds and 24 current-release
uses, with both Allow and Deny outcomes. It imports neither Examples nor Tests.
The medical vector uses the existing delegation-attribute presence condition;
it does not reinterpret presence as an authenticated, unrevoked delegation.

The existing Rust publication-authority test interpreter independently replays
all four worlds with SDK schema validation. Its current-use boundary reads the
stored active source and current facts under the existing mutex, checks release
identity, epoch, enforcement and generation, and observes any simulated effect
before releasing the lock. All 24 results must equal Lean's output, with exactly
two admitted uses. Additional checks cover fact mutation, fresh-ticket denial,
unresolved exposure and ABA invalidation. This simulator does not authenticate
external readers, prove filesystem durability or provide a production sender.
Policy-source comparison is representation-sensitive and may conservatively
refuse a reordered but semantically equal source; it does not infer equivalence.
The older publication, CAS and registration corpora keep their original sizes.

Run =just check-gateway-delta= for the combined existing gate. Its original
120-second producer deadline, 2048 MiB Lean heap and heartbeat budget remain
unchanged. Generated inputs stay in =.lake/build=; they are not credentials.
