#+title: P0-P2 shared native preparation acceptance
#+options: toc:2

* Integrated scope and delivered owners

This unit implements the accepted shared-preparation plan across all 51 catalog
entries, 23 schema-bearing and 24 raw manifests, nine typed object families and
four Production artifacts. PR #8 remains open and unmerged. No per-industry
implementation, cache provider or independently declared slice is introduced.

P0 records high-resolution observer wall time, OS-reported command wall/user/system
CPU time, reporting precision, process identity/exit and RSS. A freshly copied
executable and two repeat invocations use the same complete native benchmark.
All original ordinary/instrumented/Lean workload gates remain required.

P1 is implemented in three shared owners:

- Rust EntitySlot borrows the actual schema and immutable full entity Value
  snapshots for one invocation. Only a successful snapshot is retained; full
  value equality permits reuse, changes parse and replace, and scope exit drops
  the slot. Canonical parsing stays after policy-ID checks and before request parsing.
  Direct-source batch checks use the same owner at their original parse point
  and preserve their original error prefixes. Single-case validation and the
  existing immutable disclosure PolicyBundle keep their own appropriate scopes.
  Request/context/action parsing and both authorizers run for every row. No
  decision, context, grant, credential or external fact is retained. Source
  receipt hashes are still computed from each actual Case input.
- Canonical receipt hashing borrows existing Values, writes escaped strings
  directly into the canonical buffer and encodes digest hex without 32 temporary
  strings. Exact legacy-byte tests include Unicode, escapes, nested key order,
  signed zero and integer extrema. Complete old/new replay bytes also match.
- Lean PreparedDiagnostics builds a Contract-indexed pure report closure using
  fused inventory membership and constraint traversal. Its alignment theorem
  proves the entire report equals POO diagnose, including refusal order; check
  uses that witness to construct the original Checked evidence. No object
  admission/value/result is cached. Thirteen object/report/retention laws pass
  the existing standard-axiom audit. All prior proof audits remain gates.

The independent test path forces fresh Entities parsing and original policy
loading for all 23 schema and 24 raw manifests. It compares complete receipts,
changed actions, changed invalid entities and simultaneous policy-ID/entity/UID
faults. Additional tests cover same-UID changed attributes, A/B/A replacement,
malformed parse followed by retry, fresh context changing allow to deny, schema
changes and invocation retirement. Generic Rust lifetime/borrow ownership binds
sources and the actual schema; these tests are execution evidence, not a Lean
proof of the Rust compiler, Cedar parser or external facts.

** Measured choices and rejected alternatives

Direct typed JSON transport was assessed and not enabled: direct Manifest
serde decoding rejects duplicate known fields that the existing Value-normalized
catalog accepts using the last field. A regression test preserves that wire
behavior. Safe borrowing/buffer changes landed within the existing normalization
owner; there is no second parser/configuration layer.

An inline-only Lean candidate had identical allocation counts and was withdrawn.
Eagerly staging lists improved populated profiles but added setup on missing
inputs; that candidate was replaced by the proved fused traversal. The final
variant reduces populated/refused-present allocations and leaves missing-input
counts unchanged. No upstream LeanPOO code, unsafe object mode, global interning,
compiler profile, LTO switch, dependency pin or build-job environment changed.

* Resource and replay evidence

Every complete sample still has 1280 rows, 2560 compiled/rendered authorizations,
221 source-policy loads/prepared revisions and all 51 catalog stage observations.
It performs 53 entity parses, 1227 reuses and six replacements with one retained
slot entry. The input has 51 distinct per-manifest entity snapshots; ordered
A/B/A churn accounts for the extra parses. These counts are derived independently
from the actual ordered input in the Rust benchmark, not hard-coded as a speed
threshold. The slot bound is logical retention, not a whole-process heap bound.

Allocation instrumentation remains a separate executable; ordinary latency is
measured with the normal allocator. Final instrumented samples observed
4,702,422 allocation requests and 984,631,100 cumulative requested bytes per
replay. The previous accepted cohort observed about 6.84 million requests and
1.219 GB. Instrumented wall time is not ordinary latency. Requested bytes are
allocation traffic, not simultaneously live memory or OS RSS.

repeated invocations; hashing reads its bytes before execution, so this is not
a cold-filesystem experiment. All three run the unchanged full catalog.

OS time values here have 10 ms reporting precision; the receipt records actual
precision. Observer minus OS wall may reflect rounding/supervision/scheduling;

is asserted or bypassed, and no first-execution speed guarantee is claimed.
This closes the measurement distinction without relabeling residual time as
Cedar authorization or hiding it inside a relaxed timeout.

executions), the two real-artifact mutation/original-workflow tests, ordinary
release and independent allocation/launch benchmarks, 11 Python process/artifact
