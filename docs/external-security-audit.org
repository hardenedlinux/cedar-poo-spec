#+TITLE: External Security Implementations: Gap and Integration Audit
#+LANGUAGE: en
#+OPTIONS: toc:2

* Scope and conclusion

This is a static, source-based audit dated 2026-11-03. It compares nine external
repositories with SPEC commit =9c04814= and selected current Weaver execution
sources. External deployments and test suites were not executed. Repository
stars and README claims are not security evidence. Findings distinguish missing
contracts, incomplete application refinement and optional product integration.

The useful common improvement is an end-to-end binding from authenticated fact
sources, through reviewed policy publication and current admission, to the exact
mediated effect and independently checkable outcome. Do not add nine security
engines, replace Cedar or move transport/database implementation into Lean.

* Corrections to the supplied comparison

- agent-custody does not generally forward a protected call when its precommit
  log rejects authorization. Enforcement withholds it. Its observation mode has
  an explicit non-strict, non-financial forwarding exception. An empty precommit
  configuration is another distinct case. These modes must not be conflated.
- OpenFirma's proxy integration requires traffic to traverse its boundary.
  Respecting HTTP_PROXY/HTTPS_PROXY is not proof against an adversarial process
  opening another route. Credential isolation and network coverage are separate.
  Its advertised policy-push delay is not immediate source-of-truth currentness.
- Weaver already owns provider consumption, durable unknown ranges, a private
  by-value ProviderRelease bound to session/plan/digest/format, and final checks
  around queue insertion. Generic filesystem descriptor binding remains a
  different, resource-specific obligation. Neither capability starts from zero.
- SPEC already exports schema-bound inputs and Rust already performs strict
  validation. The interoperability gap is a maintained, versioned external
  contract with compatibility tests, not the absence of schemas.
- Existing P-256/JWS mandate verification is not missing cryptography. Binding
  authenticated originating-user/MFA/audience/session facts to actual use is
  the open application integration; copying HMAC would not itself solve it.
- Current release coherence is implemented at =9c04814=: ongoing admission binds
  active root, exact policies, enforcing mode and epoch. Complete Host/IO trace
  refinement and independent fact authenticity remain open.

* Integrated delivery order and acceptance

P0 fixes the shared contracts before new transports:

1. Extend the existing observation/admission vocabulary with source-bound field
   evidence. A caller-written provenance label must not satisfy a verified-source
   requirement. Bind issuer, subject, audience, validity, source generation and
   exact attribute meaning. Signature validity does not imply semantic truth.
2. Bind the edit/review artifact to the exact policy/schema/source revision at
   publication and again to the active current-use receipt. Candidate editing
   may precede analysis; activation must require the bound result. An editing
   session identifier alone cannot prevent reuse against changed contents. Unknown solver
   results, stale analysis and governed gains remain distinct outcomes.
3. Define versioned external schema/receipt input and effect identity. Preserve
   existing POO Contract/Session and strict Cedar validation. Keep reusable
   semantics independent of transport, vertical applications and Examples.

P1 closes one complete simulated path across the existing native owners:
authenticated context, mapped action, reviewed publication, durable original
consumption, current use, exact effect handle, outcome receipt and independent
reconciliation. Require the same semantics through an MCP wrapper and one
existing native effect adapter. Shadow records possible denials but cannot
produce enforcing admission evidence. The shared Backend owns commit/recovery;
provider adapters do not each introduce a new Backend.

Acceptance includes forged provenance, untrusted MFA, expired/wrong-audience
claims, unmapped action, changed tool schema, stale review, changed active
release, resource replacement, revocation during waiting, precommit failure,
crash after send, missing outcome, duplicate provider action and an omitted
receipt. Preserve unknown exposure after ambiguous delivery. Compare full Lean
and independent Rust states/refusals, not just an Allow counter. Simulated Host
and provider records are sufficient; deployed credentials are not required.

P2 expands adapters and lineage only when a concrete consumer needs them.
SQL wire proxies remain optional. DuckDB/Arrow source lineage and GraphAr graph
storage/indexing can support explainability, dependency queries and blast-radius
analysis in the shared data architecture. They do not authenticate facts, decide
Cedar permissions or make a provenance graph complete by themselves.
