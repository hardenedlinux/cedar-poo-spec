* Algorithm and ownership

=CatalogPreparation= composes the existing finite Schema preparation with a
finite SDK syntax-use plan. The plan counts distinct complete policy sources
per actual case-bearing manifest. It retains only sources with multiple uses.
A miss still parses JSON with the public SDK, independently renders and parses
Cedar text, normalizes the text-side bodies, compares full body multiplicities,
and binds the complete source digest. Only successful immutable syntax can be
shared. Schema admission, entity slots, UID slots, request contexts, diagnostic
checks and both authorizers remain local/fresh. A checked syntax hit rebinds its
source to the current immutable source owner.

Each manifest completion, including SDK/schema/request rejection, consumes one use of each distinct source. The last
use removes its slot and releases its shared SDK owners. Unplanned sources are
prepared locally and never create a shared slot. The plan performs no SDK
admission; malformed later entries still fail at their original replay position.
The whole catalog owner is explicitly dropped in the existing cleanup phase.

The catalog producer consumes factories in entry order and immediately publishes
each result, instead of retaining the complete raw inline catalog before encoding.
Factory and publication errors stop at their entry. Each publication computes
its full compressed encoding once and passes that same value, with an equality
proof, to lookup and append. Hashes still only locate candidates. Existing
kind-indexed references, publication frame/value proofs and the actual Functional
ObjectContract continue checking complete encoded source equality.

The native diagnostic now reports =sources-ready= after both factory evaluation
and source publication. Standard generated C confirms that the old miss path
called compression once for lookup and again in append; the new miss path
compresses once, removing one full encoding at each of 220 new source insertions.
The compiler comparison uses verbatim baseline source and the same Lean compiler,
with a separate temporary module root.

The former separate =catalog-ready= mark is removed,
because no complete raw intermediate catalog exists. Pure work remains inside
the noinline IO boundary so elapsed phases cannot silently move past clocks.

* Measurement and remaining startup boundary

The fixed official process driver compares frozen baseline binaries against the
candidate, with both variants copied to fresh paths, three complete process pairs,
all object profiles and ordinary benchmark samples. It preserves all observations,
fixed workload, default Cargo concurrency, 120-second child limits and existing
memory/heartbeat gates. Instrumented allocation and diagnostic launch processes
are reported separately from ordinary timing.

The prior read-only Mach-clock/PID correlation established execution-policy and
provenance participation before main. Its log records have zero activity IDs;
thread identity alone cannot assign interleaved service work to one child. The
remaining pre-main interval cannot be charged wholesale to syspolicyd, its queue,
scanning, or the dynamic loader without more direct evidence.

Apple's [[https://developer.apple.com/forums/thread/706442][Resolving Trusted Execution Problems]] describes the relevant
execution-policy log owners. This investigation uses read-only observation of
our own child processes, preserving system security settings and binary identity.

* Direct pre-main observations and persistent producer roots

A separate diagnostic invokes the same complete catalog six times per role,
using the existing launch framework. A bounded sample targets only the first
child of each role, once, for one second at a 10-ms interval. All 12 launches
exit zero, satisfy the clock protocol and match the ordinary catalog/receipt
hashes. They do not qualify ordinary latency: sampling suspends/resumes the
child and may perturb scheduling.

The actual installed dyld is observed at =_dyld_start +0= for 15 Rust samples
and 73 Lean samples. Apple's [[https://raw.githubusercontent.com/apple-oss-distributions/dyld/main/dyld/dyldStartup.s][dyld startup assembly]] documents the kernel's
initial program counter at that entry. This locates the sampled interval at the
loader entry before observed SDK/manifest execution, rather than within Cedar
normalization or source-table encoding. The public source is explanatory, not a
claim of byte identity with the installed macOS release. Page faults, scheduling,
execution-policy queues and scanning time are not individually distinguished.

Same-PID raw-Mach policy records remain consistent with that boundary:

| Role/fresh file | Spawn to main | Spawn to provenance event | Event to main |
|-----------------+---------------+---------------------------+---------------|
| Rust 1, sampled | 523.765 ms | 514.225 ms | 9.540 ms |
| Rust 2 | 668.391 ms | 666.250 ms | 2.141 ms |
| Lean 1, sampled | 1393.708 ms | 1252.852 ms | 140.856 ms |
| Lean 2 | 2166.575 ms | 2031.794 ms | 134.781 ms |

The actual call graph then shows Lean module initialization executing
=Functional.prepareProgram=, C4 linearization in the AWS handoff/lineage path,
and Health/Agentic manifest/program preparation. The existing import clock
brackets approximately 89–92 ms of initialization in this diagnostic cohort.
The generated =AgentDataFlowValidatedExport= C initializer explicitly evaluates
the manifest and calls =lean_mark_persistent= on it. Its upstream raw exporter
similarly evaluates and persists its manifest during import.

Consequently, incremental factory consumption removes an extra raw output list
but does not retire these persistent imported JSON/program globals. It must not
be described as eliminating all producer materialization or reducing its RSS.
This explains why removing the duplicate append encoding and SDK work alone
cannot establish stable whole-process acceleration.

* Next shared algorithm boundary

The remaining producer work belongs at the common typed case/source publication
boundary. A complete migration should give each immutable policy/entity/schema
snapshot one encoded representation and pass kind-indexed proof-bearing snapshot
references into both standalone and bulk projections. Merely wrapping existing
persistent manifest values in Unit factories will not remove their initializer
work. The required law is full expansion equality with each existing authoring
manifest, alongside the actual Functional Contract and publication frame/value
laws. All applicable raw/schema-bound cases, schema evolution, named policy
artifacts and cross-artifact consumers must migrate together.

Remaining SDK normalization must preserve the independent text parse, complete
body multiplicities/diagnostic mapping and fresh strict validation. Any deeper
canonical representation should use supported SDK interfaces; private AST access,
source hashes, policy IDs or cached decisions cannot replace those obligations.
A new candidate must repeat empty-artifact cold build and the same complete
process/resource protocol before claiming end-to-end acceleration. The OS loader
entry wait remains a separate diagnosis, not a reason to increase workload limits,
change system security policy, or present only warm/focused timings.
