* Scope and owners

The [[file:gateway-effect-v1.schema.json][versioned schema]] defines the boundary representation. Native serde types
and admission checks reject unknown/duplicate security fields and unsupported
major/minor versions. Schema validity alone grants no authority. Facts use
per-field source policy, not caller-selected provenance labels.

[[file:../../CedarPooSpec/ZeroTrust/Evidence.lean][Generic fact evidence]] carries issuer, subject, audience, source, field,
value commitment, source generation, origin and validity interval. The
independent authority supplies expected bindings, required inventory and the
verification interpretation. Claimed, unverified, omitted, duplicate, extra,
expired and substituted fields refuse. The general theorems retain each exact
current binding and the complete required inventory.

[[file:../../CedarPooSpec/Gateway/EffectProtocol.lean][The shared effect Contract]] additionally binds protocol version, exact
operation/object generation, request payload, action schema, audience and the
registered review's before/after policies, schema, source, epoch and report.
It requires enforcing mode, a mapped operation, no revocation, original
consumption and no unresolved exposure. The native simulation consumes an
exact-effect grant through the existing =authority_consumption::AuthorityLedger=
owner before preparation; an envelope cannot supply its consumed count. The POO requirement strengthens the
independently selected original; existing Contract/Session constructors remain
the owner. The typed Cedar receipt composition retains actual error-free Allow.
A source or review label is never a send capability.

* Native module ownership

The optional runtime owner remains =cedar_poo_runtime::gateway=. Its
[[file:../../rust/runtime/src/gateway/mod.rs][public boundary]] exports typed protocol values, source authority, witness,
audit and simulation APIs. Separate files own wire verification, immutable
source preparation, witness history, provider observations, reconciliation,
serialized simulation and indexed lineage. Recovery evidence and borrowed
execution channels have explicit types. The default runtime and bridge do not
acquire the optional P-256 dependency; isolated feature checks enforce this.

* Native representation and cryptographic boundary

The optional Rust =gateway= feature uses existing workspace P-256/ES256 and
unpadded base64url. Signed payloads are exact UTF-8 JSON bytes of typed records;
verification checks those original bytes before accepting their meaning. Operation
IDs hash the versioned typed tuple of revision and Case name; delimiter-joined
identifiers are not used. A native regression checks current slash refusal,
typed tuple encoding and cross-operation refusal separately. Current revision
validation already excludes slash aliases; this is not an exploit claim. Field
separators, caller public keys and self-declared verification flags are not
accepted as authentication. Fact authorities select keys from independent
issuer policy and require exact expected source/meaning/value/lease bindings.
The prototype uses separate binding/context/entity source keys, a gateway key
and a witness key. Its fixed simulation scalars are public test material and
must never become deployed trust roots.

A prepared source authority retains verified immutable bytes/signatures and
source bindings. Inventory, exact candidate bytes, source generation and time
are still checked at every use; changed material takes the signature verifier
again. This preparation is not a cached authorization decision. New issuer
policy needs new preparation. A different schema or world does not acquire an
old Cedar decision. Native word counters refuse exhaustion before mutation. Signers and public
verifiers share the same 1 MiB payload limit, tested at the exact byte boundary.
A post-send outcome-signing failure retains unknown exposure and issues no
complete receipt.

Nonidentity activation now uses the existing =Authorization.Delta.Release=
and =Gateway.PublicationReview= owners in the same shared simulation as current
effects. [[file:../../CedarPooSpec/Gateway/ReviewedEffect.lean][The reviewed-publication POO Contract]] checks the exact =advanceReviewed=
successor. Its kernel laws join that successor, the actual installed policies
and the current typed Cedar receipt. A separate theorem retains the existing
=PublicationReview.Final= original Contract, registration and Zero Trust
premises. These are conditional composition laws: authenticated Host facts and
solver completeness do not follow from them.

Each real Case retains its proof-bound original C4 model/root. =SchemaSource=
retains the native Schema with an encoding equality proof. These semantic fields
do not alter the existing wire representation. The Production workload appends
a fresh C4 diamond that adds an unconditional forbid, then a second diamond
that removes it on one branch. Original declarations, parent order, edits and
policy IDs remain intact. The ordinary =Delta.analyzeAndCapture= analyzes both
legs against the real Schema; the Rust SDK independently replays gain witnesses.
The simulation's review authority signs this exact analyzer output. A distinct
mock authority approves expansions, binding the complete signed review and its
epoch. A caller-supplied classification, approval bit or MCP argument cannot
supply either authority. This does not turn a solver report into ExactCoverage
or implement a new policy analyzer.

Registration authenticates the original C4 source, current root/policies,
Schema, world and epoch, then prepares the actual candidate with the SDK.
A private owner/generation ticket binds publication to that registration.
Publication installs the candidate Case and its SDK receipt under the same
mutex used for current effects, advances the policy epoch, and invalidates old
prepared handles. The original =AuthorityLedger= consumption is retained.
Restoring equal policy bytes does not reactivate an old review: the C4 root and
epoch have advanced. The fixed mock keys are independently assigned to facts,
review, gain approval, gateway and witness; none are deployment credentials.

* Order, recovery and independent reconciliation

Native preparation produces a private, owner-bound, by-value effect handle.
Every model writer advances its non-reused generation. Final use checks the
handle and current source/policy/object image under the same deciding mutex.
The independent witness accepts a signed precommit before the provider journal
records the simulated effect. A log failure prevents sending. A crash after
send retains the burn and unknown exposure, with no outcome receipt. A complete
receipt carries the signed precommit, source evidence, signed publication prefix
and provider observation. The witness commits the publication digests before
the effect. The public auditor checks each review, independent expansion
approval, successor policies and contiguous publication epoch/prefix; it refuses
missing review trust and nonidentity receipts without their publication history.
Recovery requires independent witness and outcome/provider records; it cannot
restart the original operation or convert a missing outcome into success.
Publication reply loss and effect outcome loss are separate exposures. A lost
publication reply leaves the actual successor installed and blocks further use;
only an exact authenticated prefix read clears that publication exposure. It
cannot clear an unresolved effect. The single =Simulator::recover= entrypoint
requires the surviving trusted current authority, exact publication prefix and
independently configured historical audit window. It never reconstructs live
authority from Case bytes or historical receipts. Recovery preserves the actual
policy epoch, source inventory/generation/clock, revocation, mode, consumption
and publication exposure, then reconciles effect uncertainty. Replacing the
mediator invalidates old handles and fences all writers of the retired owner. This is an in-memory simulation, not crash-durable storage
qualification.

The public auditor needs no private signer. It receives a signed checkpoint,
public log entries, gateway receipts and independent provider observations.
Trusted gateway/log/source keys, expected historical field bindings, observation
time and a minimum checkpoint size come from its own configuration. The
=minimum_size= floor must be retained or independently fetched; an old signed
checkpoint is not proof of currentness. The verifier checks chain continuity,
checkpoint size/root, source signatures/inventory and exact precommit/outcome
bindings, then reports unresolved precommits, missing receipts, orphan receipts, changed effects,
duplicates, invalid receipts and an invalid log separately.

Provider enumeration completeness, real fact truth, trustworthy clock readings,
key custody, physical durability, nonrollback storage and external IO mediation
remain adapter obligations. A signed observation does not become a provider
attestation. Simulation forks create disjoint test worlds; they are not live
ledger rollback APIs. Independent reconciliation is bounded by the supplied
provider window and independently pinned checkpoint.

* MCP boundary

=cedar-poo-bridge gateway-stdio MANIFEST --enforce= or =--shadow= runs a fixed
schema-qualified simulation profile using the same native admission owner.
The manifest and source adapter are independently configured; request
=clientInfo= and caller provenance labels establish no identity. Arguments must
match the profile's actual projected request. A supplied envelope is checked;
otherwise the independent simulated source adapter supplies its own evidence.
Unmapped tools refuse. Shadow reports =would_deny= and issues neither an
enforcing receipt nor an effect. Mode is explicit at process startup.

=gateway-reviewed-stdio BUNDLE GROUP_INDEX --enforce|--shadow= loads trusted
Lean analysis at startup, publishes both real nonidentity revisions, and serves
the same MCP admission owner with the installed successor. Startup fixtures are
an administrative input, never =tools/call= arguments. Enforce and shadow child
processes verify the two-publication receipt and read-only shadow behavior.

The implemented binding follows the official [[https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio][2026-07-28 stdio specification]]:
newline-delimited JSON-RPC, per-request version/client metadata,
=server/discover= and typed =tools/call=. It supports =tools/list= and =ping=;
legacy initialize negotiation is not advertised. Discovery/client metadata is
not authentication. Security-bearing envelopes are decoded directly from the
original frame to retain duplicate-field rejection. Frames are bounded to
1 MiB, stdout contains only protocol messages and EOF terminates the process.
The endpoint forwards no external traffic and implements no OS sandbox.

* P2 lineage and optional transport/data integration

Source-to-operation edges are built from verified precommits and independent
provider observations. A reverse index answers affected-source queries; the
Lean affected-set law defines exact membership. Precommitted-only and
provider-observed edges remain distinct, including missing-outcome cases.
The versioned graph-neutral export is an input to a consumer-owned GraphAr/Arrow
adapter, not the GraphAr storage format or an authorization result.

GraphAr remains the strategic graph storage/index layer. Optional DuckDB/Arrow,
HTTP interception and SQL wire adapters belong to concrete consumers and share
the existing Backend's commit/recovery contract. No new SQL backend, per-provider
Backend or Cedar-to-MRR dependency is introduced. Physical GraphAr/Arrow IO and
arbitrary external MCP/HTTP proxying are not implemented by this simulation.

* Continuous authorization boundary audit

This revision closes current-state gaps left by the initial reviewed-effect
integration. The implementation follows the input boundary of the official
[[https://docs.cedarpolicy.com/auth/authorization.html][Cedar authorizer]]: a decision uses the request, policies and entity data supplied
for that evaluation. Their authenticity and freshness remain application duties.
[[https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf][NIST SP 800-207]] assigns monitoring and connection termination to enforcement
components. The modeled boundary here is each discrete mediated effect, not
arbitrary network streams or complete NIST/UCON certification.

| Boundary | Finding and implemented check | Remaining interpretation |
|----------+-------------------------------+--------------------------|
| Source renewal | Stored source preparation had no authoritative update path. The trusted simulated adapter now signs a new exact field inventory, lease, world commitment and strictly newer fact generation, then runs the SDK on the candidate entity world. A valid update starts by closing source readiness; failure leaves old cached material unusable. Only actual successful SDK/source preparation reopens it. Every writer invalidates old handles and registrations. | Source truth, trusted clock observations and real issuer custody still come from adapters. No renewal API is exposed through MCP caller metadata. |
| World binding | Independent field authenticity alone did not connect each fact's source to the SDK world. Admission and independent audit now require every accepted fact source to equal the explicit =current_world= committed by the envelope/witness. | =ReviewRecord.source= binds C4 declarations; =ReviewBinding.source= retains the pinned publication world; =current_world= and fact sources bind the fresh SDK request/entity world. These are distinct identities. |
| Policy publication | A fresh fact world must not be spliced into a pinned publication history. The original equality of publication worlds remains enforced; registration and publication now refuse a mismatching current world or expired facts. | A different-world policy publication needs a separately bound release-chain protocol. It is deliberately refused here. Restoring identical world bytes still requires new fact generations and a fresh current registration. |
| Revocation | A Case/history-only recovery could recreate unrevoked defaults. Revocation is now terminal for the original operation and survives source refresh, publication confirmation and recovery. | It cannot retract an already observed external effect. Real streaming/buffered transports must mediate each consequential drain or provide their own fencing refinement. |
| Recovery | Replaying authentic history did not establish current authority. Recovery now reads and updates the surviving authoritative state under the deciding mutex; exact history and audit trust can reconcile an outcome but cannot reset current controls or remint the original grant. | The trusted in-memory authority must survive the modeled mediator failure. Physical nonrollback storage and cold-host restart remain Backend obligations. |
| Mediator ownership | Generation alone did not retire an old facade that could prepare again. Recovery now rotates the authoritative owner under the deciding lock; old facades cannot refresh, revoke, confirm, publish or use. | Production distributed ownership needs a real external fencing implementation. A process mutex does not supply one. |
| Historical audit | Current source bindings must not be retroactively substituted for a completed effect's historical window. Recovery takes explicit independent audit trust and preserves the current source image. | A historical receipt can resolve that outcome; it grants no authority for a new effect or a new world. Missing outcomes retain unknown exposure and the burn. |
| Request changes | Request context may contain business parameters as well as authorization data. Fact refresh preserves the complete original request, policies and Schema and changes entity evidence only. | A changed request/context requires a newly authorized logical operation; the current implementation does not silently reinterpret the original effect payload. |

[[file:../../CedarPooSpec/Gateway/Lifecycle.lean][Lifecycle]] uses the public POO =Contract.withMeaning= operation to strengthen
the existing exact-successor publication Contract with current evidence, matching
policy epoch and the pinned world. Its use Contract returns the exact current
outcome. Kernel laws retain the original reviewed successor, reject changed-world
publication, invalidate old handles, preserve the clock and consumption across
renewal, and preserve revocation and burn across recovery. The fresh-use theorem
still requires the actual current typed Gateway/Cedar receipt; it does not infer
Allow from an old review or a signed fact label.

The shared Production workload adds a genuine C4 tightening diamond inheriting
from the installed restored root. Its ordinary analyzer captures a fresh epoch-9
no-gain review; branch/base topology is checked by the existing Delta owner.
One Program prepares all roots and projects current and empty-entity worlds.
Each applicable Case exercises expiry, renewal, entity change, pinned-world
publication refusal, equal-value world restoration, fresh policy tightening,
revocation and both complete/uncertain recovery. The current-world probe performs
a real native simulated send and public reconciliation in a separate test world;
a successful prepare is never reported as a completed send by itself.

=just check-reviewed-effects= retains all original reviewed Cases and adds
=gateway-lifecycle-catalog= using the same source fixtures, signatures, SDK,
publication owner and admission lock. Each native process keeps the existing
120-second limit. Lean owns the actual Case construction, POO Contract outcomes
and proof laws; Rust compares complete outcomes and current controls. Python
remains an external process/resource observer. Experimental topology failures
and failed local observations remain local evidence, not successful samples.

A failed source refresh is a distinct state from an unresolved provider effect.
The simulator closes source readiness before evaluating an eligible update;
a parser/Schema/lease failure leaves live use and publication closed even when
the previous signatures and lease still verify. Recovery preserves that state.
A successful fresh source preparation can repair it, while preserving revocation,
original consumption, spent status and unresolved provider exposure. A request
or policy substitution is refused before it is treated as a source update.
Publication also requires the exact consumed original and an unspent operation.

The full current-state matrix has thirteen complete outcomes per qualified Case,
including failed refresh, failed-source recovery and repair. Current and
historical source windows remain separate: a current verifier cannot silently
stand in for historical source configuration, and a historical audit result
cannot reopen current authorization.

The draft version-1 envelope and witness precommit now require an explicit
=current_world=. It is distinct from the pinned publication world's
=ReviewBinding.source=. Both original publication checks remain: consecutive
publication worlds are equal and the effect's review source matches the last
publication world. Fresh use adds its own world/evidence equality without
removing either check. Missing, duplicate or substituted =current_world= refuses.
This unmerged draft representation is intentionally strict; no fallback silently
upgrades older envelopes or log records. Read-only lifecycle observations are
not deserializable recovery authority.

Review artifacts remain reusable only within their exact C4 source, Schema,
root/policy and epoch scope. A new source generation invalidates registration
and prepared-use capabilities; it does not pretend that a global same-Schema
Delta analysis became a new physical fact observation. Re-registration still
checks the current source lease, pinned publication world, original consumed
unspent authority and the SDK-prepared candidate. A policy-epoch change rejects
the old review artifact itself.

* Issuer-bound source preparation

The native CPU sample identified per-field P-256 signing and verification in
=prepare_facts= as material construction/renewal work. The signed payload algebra
now explicitly admits either one =FactBinding= or a version-1 =FactStatement=
containing a nonempty list of complete bindings. The simulation publishes one
statement per independent issuer. This is not an ECDSA batch-verification scheme.

For F fields, I independent issuers and B payload bytes, the old path needed F
signatures and F verifications; statement preparation needs I of each, while
retaining all F field checks and hashing/encoding B bytes. Issuer grouping never
combines trust roots. The verifier selects its key from the independently retained
expected field inventory, rejects mixed issuers, checks every complete binding,
and requires exact duplicate-free coverage across all statements. Unknown
versions, empty statements, foreign keys, altered signatures, omitted/extra fields,
claimed facts and expired leases refuse. The original single-field form remains
an explicitly supported wire alternative, not a failed-verification fallback.
Both forms retain the 64-KiB decoded-field bound; complete signed statements retain
the existing 1-MiB payload bound. Exact known bytes may reuse signature preparation,
but current inventory, world, lease and sticky controls still check on every use.

=FactStatement= is also a typed Lean source projection. Kernel theorems establish
that accepted statements are independently verified, do not mix issuers, and
preserve =FactAuthority.acceptsAll= over the complete flattened inventory.
The shared Production renewal oracle now invokes =Lifecycle.sourceContract=;
its invocation theorem binds returned fields to the original field admission.
These are refinement proofs under the stated Host verifier interpretation,
not a Lean proof of P-256 or of physical source truth. Rust tests exercise actual
signatures, separate keys, tampering, duplicate/omitted fields, stale leases,
changed generations and exact single-field/statement result parity.

Renewal now captures only schema ownership, clock, payload and generation metadata
under the deciding lock. It no longer clones the complete Case, signed facts,
publication history and original ledger merely to prepare a successor. Request
fields and policy source identities compare directly using the existing public
complete-source equality, including signed-zero distinctions. No digest-only
comparison or decision cache replaces those checks. Sources close before SDK
work and reopen only after fresh SDK interpretation and an exact-generation
install; concurrent writers, revoked/burned state and failed preparation retain
their existing refusal behavior. Construction also reuses the already computed
world/policy identities rather than serializing those sources twice.

The first statement run covered the same 51 entries, 1,253 Cases, 39 refusals
and 635/618 allowed/blocked populations. Construction p95 was 22.482 ms and
renewal p95 17.737 ms, versus the earlier 44.154/43.726 ms observations. Process
CPU was 22.390 versus 50.090 seconds. Several SDK, warm-admission, publication
and send percentiles worsened; all remain non-wins. The new per-Case sample
retention also changes benchmark-buffer lifetime, so its 119,291,904-byte RSS
cannot establish request-memory improvement against the older observer layout.
A single run does not establish stable whole-process acceleration or an SLO.

Native output retains every Case's individual timings, identity, population,
field count and evidence-unit count. It also retains every growing-log timing
in operation order. Console summaries and per-Case sample lines are separate; CI logs retain all
timing samples, including non-wins, without publishing signed protocol payloads.
The native generated JSON also retains the complete observations. No CSV, archive, HTML or vendor
output is committed as performance evidence.
