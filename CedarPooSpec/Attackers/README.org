* Ownership

=Attackers/= owns reusable attacker capability graphs, executable action traces
and LeanPoo objects. It imports no industry, Gateway, Examples or Tests modules.
=Vertical/= owns application-specific effect contracts. =Examples/= binds
attacker objects to actual application writers; =Tests/= owns rejection and
deliberately unsafe controls. Hand-written Quint projections live in
[[file:../../dev/qnt/README.org][dev/qnt]], not alongside the Lean library.

* LeanPoo object family

[[file:ProfileObject.lean][ProfileObject]] uses typed Dataflow slots =initial=, =rules=, =isolated=,
=goals= and a derived =model=. A root Model is a type index; the derived
Certified model retains its initial attacker powers, rules, declared independent
boundaries and verification goals. Validity refuses duplicate inventories,
empty goal names and acquisition/initial control of an isolated authority.
Changing that premise requires an explicitly different root threat model.

=augment= cooperatively extends slots; =derive= can declare a sibling in the
same source family; =mix= delegates C4 multiple inheritance to LeanPoo.
Shared-base diamonds use one source and one declaration owner. They do not
merge separately copied base graphs or implement another precedence algorithm.
The inherited =model= resolver reads final self, so a slot replacement must
recompute certification rather than retain a stale parent certificate.

=Session= uses the existing ObjectProfile Contract/factory. Root retention
alone cannot preserve additional constraints introduced by an intermediate
parent. =selectSessions= therefore compares the actual selected model against
each independently required parent Session. Source-bound reads and both root
and parent retention are exposed by =selection_retains_actual_parent=.
Parent selection is an application authority decision, not caller metadata.

The [[file:../../Tests/Attackers/ProfileObject.lean][object tests]] derive payment and health fixture branches from one root,
compose their distinct rules/goals, reject broken isolation, and retain a
counterexample where a raw override passes the root Contract but loses a
parent's attacker powers. Effective parent selection refuses that override.
These fixtures demonstrate cross-vertical reuse, not healthcare deployment.

* Attack traces and proof scope

[[file:Trace.lean][Trace]] distinguishes acquiring a capability from calling an application.
Acquisition requires a listed rule and every prerequisite. Calls require the
supplied reachability interpretation and use the application's actual writer.
Refused attempts are counted; they do not magically acquire authority.

=run_preserves_absence= proves non-acquisition of an initially absent capability
that no rule grants. =run_preserves_outputs= lifts the actual writer's output
law through arbitrary finite action sequences. =certified_isolation= obtains
the capability premises directly from the selected POO model. These are generic
kernel proofs, not exhaustive physical-environment discovery.

Goal strings name obligations for domain-specific checks; they are not proofs
or runtime grants. The financial case binds goals to exact payment effects,
authenticated workloads and deployment isolation. Other verticals supply their
own writer and discharge the corresponding output property using the same
object and trace mechanisms. Unknown exported goals must fail projection.

The [[file:../../Examples/Scenarios/FinancialServices/Wallet/README.org][financial acceptance audit]] records source evidence, all trust premises,
the actual C4 object specialization, finite Quint interleavings, native-decision
axioms in closed fixtures, and unsafe-verifier/bypass counterexamples. Graph
completeness, independent trust roots, authentic current facts, complete effect
mediation and durable nonrollback execution remain explicit Host obligations.

* Checked application writers

A =Certified= object certifies its actual acquisition graph and retained parent
requirements; it does not certify an arbitrary application =invoke= function.
The lower-level =surface= constructor remains available for explicit models and
countermodels. =CheckedWriter= carries the application owner's required output
predicate and a preservation law; =Certified.checkedSurface= requires that law
at construction. =checked_outputs= reuses the existing arbitrary-finite trace
proof while retaining the selected C4 model. Neither labels nor the word
“checked” authenticate the owner's native interpretation or grant physical IO.

The wallet differential replay uses a fixed fixture requirement in its guarded
lane and proves that its unchecked relay cannot supply the same writer law.
Generic construction laws and fixture-dependent decoder/graph proofs retain
separate axiom audits. Other verticals can supply their own typed output meaning
without copying the capability graph or trace proof.
