* Review provenance and publication composition

=Delta.Release.ReviewedInteraction= has a private constructor. Its public API
allows reading a captured analysis/snapshot but not splicing them through record
construction or update. =analyzeAndCapture= is the supported producer. This is an
API integrity boundary, not cryptographic authenticity or a proof of solver UNSAT.

The application adapter =CedarPooSpec.Gateway.PublicationReview= uses actual
LeanPoo =Contract.bindEvidence= and =Invocation=. It binds the exact command,
independently read parent, approved artifact and current cut while preserving the
original invocation rule. Its =Final= also requires generic ZeroTrust guards,
command-specific pending admission and the Host's actual commit relation. An
administrative command may resolve its own staged intent while siblings remain;
the provider effect's global pending barrier remains separate. No IO or second
ledger is implemented. Trusted reference interpretation, durable registration,
atomic current-state join and native transition refinement remain Host premises.

* Ownership

=CedarPooSpec.Authorization= aggregates the reusable authorization capabilities.
=Compound= retains the existing POO policy compilation and combined decisions.
=Delta= aggregates the modules under =Authorization/Delta/=.

| Delta module group | Responsibility |
|--------------------+----------------|
| Model / Proof | Revision analysis and conditional Cedar symbolic-query soundness |
| Operational / OperationalExact / OperationalExactProof / BooleanCore | Error-free execution differences and exact-query proofs |
| Reasons / EffectiveReasons / EffectiveReasonsProof | Decision reasons and their checked interpretation |
| Compound / Evidence | Existing functional C4 policy composition, source/proof provenance |
| Interaction / Release / Trace | Combined revisions, release qualification and finite sequential comparisons |
| Json | Existing report/export boundary |

The namespace is =CedarPooSpec.Authorization.Delta=; Compound lives under
=CedarPooSpec.Authorization.Compound=. This is a direct source/import/namespace
migration. There are no forwarding modules at the former flat source paths.
Dependency pins and historical raw evidence remain unchanged.

* Relations to other frameworks

Zero Trust supplies generic effect-boundary requirements; Authorization supplies
Cedar-backed decisions and Delta analysis. Gateway consumes both using its
existing POO profile publication and explicit Host execution contracts. Neither
framework imports a Gateway implementation. Existing C4 owners, Contracts and
proof dependencies remain the authorization composition mechanism.

The mathematical meaning and solver trust boundary remain those in
[[file:../../docs/rfc/0004-authorization-delta.org][RFC 0004]]. File organization
does not extend a same-world policy theorem to mutable execution trajectories.
