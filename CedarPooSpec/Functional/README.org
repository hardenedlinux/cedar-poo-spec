#+TITLE: Functional Cedar capabilities

* Exact data and typed operations

[[file:../PolicyPreparation.lean][PolicyPreparation]] owns =Compiled model root= and
=Validated model root schema=. Their fields contain actual compiled policies
and the corresponding compilation/schema/policy equations. =PolicyJson.Publication=
extends this validated value instead of duplicating its witness fields.
The compatibility publication API delegates to these stages in its original
compile/definitions/well-formedness/policy/export/unique-ID order.

[[file:Capabilities.lean][Capabilities]] uses LeanPOO =Factory=, =Provider= and C4 assembly with a
dependent result type for =compile=, =validate=, =publish= and =authorize=.
Later stages consume the exact earlier-stage data. =Requirements.prepareConsumer=
resolves the complete capability list before building any context.

=Coherent= is the shared method contract: the selected authorization method
must return responses from Cedar for the actual checked policies, requests
and entities. =coherent= proves this from the operations' indexed witnesses;
=CertifiedConsumer= passes that proof into =construct=. It is not an assumed
Boolean assertion about a provider name.

=Ready.allowed_eq= proves that admission uses Cedar's actual responses,
requires a nonempty request list, and refuses any policy-evaluation error.
Industry object Contracts continue to guard their configuration and projections
before those policies enter the model. Cedar request/entity evaluation remains
distinct from authenticating Host-supplied facts.

* Preparation and consumption

The payment and medical consumers show the full public sequence:

1. Construct typed industry objects and admit them through their Contracts.
2. Compose the policy model with the existing C4/Edit interface.
3. Call =prepareProgram standard model schema roots= once and retain its result.
4. Call =program.authorize root requests entities= for current inputs.
5. Use =receipt.allowed= at the existing business-effect boundary.
6. Call =program.publish= or =program.authorizationCase= for validated exports.

The constructor uses =Validation.traverse= and returns the first preparation
error, without exposing a partially prepared Program. Duplicate root requests
are eliminated in first-occurrence order. Each retained root holds checked
policy data and a lazy publication thunk. Export is not demanded during
authorization, and repeated exports share this immutable serialization result.

=Program.at= preserves the existing open-root interface: a valid root outside
the retained set uses the same already selected factory. It receives the same
compilation and validation gates and can be explicitly retained by a subsequent
preparation. Unknown roots preserve their underlying compilation failure.
There is no direct-authorization fallback for unprepared roots.

The Program is indexed by its actual captured model and schema. It never
compares opaque factory functions, assumes DecidableEq over a model, or keys
reuse by a profile/root name alone. Changing model or schema requires a new
appropriately indexed preparation. Requests, entities and final decisions are
not cached. An old Program remains an explicit old snapshot; its type does not
authenticate a current external Host revision. Real Host publication/release
still needs the existing source/scope/revision checks at the effect boundary.

* Effectful admission consumers (C2)

[[file:Admission.lean][Functional admission]] bridges checked data to the existing
=Admission.PolicySnapshot=. =Ready.policySnapshot= preserves the exact root and
whole policy set. =Program.refreshPolicy= first obtains checked data at the
captured root from its supplied Program, then compares the complete policies.
Its =Refreshed= subtype carries the equality witness. Compilation/schema/policy
refusal is =RefreshError.preparation=; unequal policy bodies or order is
=RefreshError.changed=. Export is still deferred.

=Ready.policySnapshot_compiled= and =Refreshed.compiled= bind both sides to
actual model compilation. =Refreshed.allowed_eq= ties each new request/entity
decision to the exact captured policies. These are kernel proofs with no native
Case computation assumptions.

- [[file:../../Examples/Health/AgenticAI/LanguageModel/Disclosure.lean][Disclosure]] uses its checked Program for fresh projected requests in both
  prepare and redeem, and for its complete manifest. DeployableRoot remains
  restricted to composed roots. Epoch, approval/delegation/policy/audience
  revisions, exact effect, expiry, current grants, lineage, audit, budget and
  cumulative cohort checks remain domain-owned. Only successful redeem advances
  epoch, spends budget and records the actual payload digest.
- [[file:../../Examples/Enterprise/Agent/Fanout/CrossAgentEgress.lean][CrossAgentEgress]] uses selected checked authorizers for diagnostic replay
  and prepare/commit. Each prepare/commit builds a Program from the actual
  =activeModel= argument and schema; commit never substitutes the global fixture
  Program for that argument. It refreshes the existing snapshot before actual
  request evaluation, then consumes the exact grant and admits the operation
  before advancing lineage/budget/epoch. The worker allowlist remains explicit.
  =Factory.fold= sequences replay with the request projected before each step.
  Raw =authorizedBy= remains an independent policy-only diagnostic for the
  changed-policy theorems; it is not the admission path.
- [[file:../../Examples/Enterprise/Personnel/SourceCustody.lean][SourceCustody]] uses current Operation.request and caller-supplied Entities
  through Program for decisions and its full schema-bound manifest. Existing
  scoped approval/delegation projection, device, departure/separation, incident,
  knowledge-scope and destination checks retain their owners. No new ticket or
  simulated external-effect lifecycle is invented for this decision-only Case.

A Program's model index describes supplied data. Calling refresh on an old
Program does not prove external source freshness. The CrossAgentEgress caller
must supply its actual active model; the admission simulation does so explicitly.
These deterministic Host simulations remain the qualification boundary. Durable
atomic execution, authentic external facts and distributed crash recovery are
separate obligations, not prerequisites for running the simulated Cases.

* Measured scoped reuse (D)

[[file:Reuse.lean][RootSlot]] is an alias of LeanPOO's =Requirements.ContextSlot=,
not a second cache implementation. =Program.rootFamily= reindexes the complete
=Program.at= outcome onto String roots. Its certified claim is exact outcome
equality, including failure payloads and the selected publication function.
The Program's actual model/schema and selected factory family remain type
indices; only root equality is checked at runtime. No DecidableEq is assumed
for an opaque model or factory, and root names/digests alone cannot rebind a slot.

The slot stores zero or one whole prepared result, including failures. A changed
root replaces the previous result; returning to an evicted root builds it again.
The same-context hit law returns retained data and the unchanged slot. Exact
value and bound laws hold for arbitrary slots, not only fixtures. Requests,
entities, authorization decisions and Host tickets are not stored in the slot.

=Ready.authorizationCase= is the shared renderer. =Program.authorizationCases=
threads one slot through an ordered batch, reevaluating each current request.
Its universal equality with ordinary =Validation.traverse= preserves all JSON
values and the first error. Medical prior-authorization and cross-agent egress
manifests use empty-retention Programs plus this batch path, removing their
nested export traversals. Their policy/state replay and admission boundaries
remain unchanged. This bounds extra prepared-root retention; input/output lists,
the caller's other Program entries and overall process RSS are not bounded by it.

=just bench-functional-reuse= runs a fixed 16-read warmup and three 128-read
samples under the existing 120-second, 2048-MiB, 10000000-tick Lean-run limits.
Each iteration changes the actual budget fact; all paths must return matching
checksums. Same-root workloads require exactly 127 hits; alternating governed/
incident workloads require zero hits. Timings are observations, never pass/fail
thresholds. The benchmark also retains the all-roots-prepared comparison.

One macOS Lean 4.34.1 sample set on 2026-10-30 measured:

| Workload (128 reads) | Repeated cold preparation | One slot | All roots retained | Slot hits |
|----------------------+---------------------------+----------+--------------------+-----------|
| Same root | 442-501 ms | 17.1-19.8 ms | 14.0-14.7 ms | 127 |
| Alternating two roots | 469-499 ms | 470-496 ms | 15.0-15.8 ms | 0 |

This supports scoped reuse for root locality. It also shows the tradeoff:
one-slot churn has no speed benefit, while full retention is faster when its
larger retained set is acceptable. These are local Lean-run preparation/evaluation
measurements, not compiled production throughput or an end-to-end manifest
speedup. The exact benchmark runs in CI, without requiring identical timings.

[[file:../../Tests/Functional/Reuse.lean][Reuse tests]] cover root eviction, cached refusal, changed source/schema/family,
changed actual requests/entities, publication refusal and complete manifest
byte equality. Five additional generic hit/value/bound/batch laws pass the
standard-axiom audit. CrossAgentEgress's dynamic commit still constructs from its
actual activeModel; this optimization never substitutes an old Program there.

B1/B2/C1/C2/D's scoped implementation is complete. Cross-source rebinding,
durable atomic persistence, process-memory bounds and native end-to-end speedups
remain outside the claims established here.

* Proof and regression gates

[[file:../../Tests/Functional/Capabilities.lean][Capabilities tests]] includes a kernel-checked universal equality between the
new publication pipeline and the independent pre-refactor algorithm. Every
success, original error and error ordering is covered for arbitrary model,
root and schema. It additionally checks:

- C4 operation override and inherited operations; exact first missing key.
- Missing capabilities precede context construction; first invalid root wins.
- A deliberately refusing publisher does not block in-memory authorization.
- Empty compound requests and unknown roots refuse admission.
- Schema changes refuse old validation; changed entities and source policies
  produce fresh decisions while the original snapshot remains unchanged.
- Medical decisions across all model roots match the old open-root behavior.
- Payment single/compound decisions and medical effects match the old consumers.
- Both complete manifests match the reference compressed JSON byte strings.
- The medical main workflow and its malformed-request manifest additionally
  match their reference bytes; all replay rows and final evidence-state flags
  match the original authorizer. A generic fold law proves state-step ordering.

A build-time audit restricts six generic API/Contract/workflow proofs to Lean's
standard =propext=, =Classical.choice= and =Quot.sound= axioms. Concrete Case
instances retain their existing native computation certificates; they are
separate from these universal method/publication/fold laws.

[[file:../../Tests/Functional/RootFamilies.lean][Root-family tests]] compare all four C1 manifests against independent
pre-migration export algorithms, compare full per-layer policies/requests/responses
including malformed, repeated and reordered checks, and compare every module
root's publication. Changed-schema and removed-source Programs cannot accept an
old Program at elaboration; a removed audit root refuses while its explicit old
snapshot remains usable. Two additional generic layer proofs undergo the same
standard-axiom audit.

Run =lake build Tests.Functional.Capabilities Tests.Functional.RootFamilies=
and =just check-lean=. Each Case retains its own source/revision/Host obligations.
[[file:../../Tests/Functional/Effectful.lean][Effectful tests]] additionally compare three complete C2 manifests against
pre-migration algorithms, CrossAgentEgress's full replay/tickets/next ledger
across both models, views and changed effects/current states, and Disclosure's
prepare/redeem/release outcomes across independently revoked or stale facts.
They test same-root policy changes, reordered bodies and invalid new schemas.
Three generic snapshot/refresh proofs undergo the same standard-axiom audit;
the Case replay-order theorem instantiates the existing generic fold law.
The complete GitHub workflow also checks the existing official Rust Cedar
parser/validator/authorizer, artifacts, scenarios and authorization-delta proofs.
Retained snapshots/thunks do not establish hard RSS bounds, Host atomicity or
a measured end-to-end speedup.
