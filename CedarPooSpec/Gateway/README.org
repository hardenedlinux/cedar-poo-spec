#+TITLE: Gateway Admission and Authorization Delta Library

* Ownership

=CedarPooSpec.Gateway= is a platform-neutral Lean library. It composes existing
Admission, Functional compilation, PolicyModules and exact operational
Authorization Delta capabilities. It adds no Cedar evaluator, solver semantics,
transport service, persistence engine or Gateway Rust runtime. The AWS AgentCore
Gateway projection remains under =Platform/AWS/AgentCore=.

Weaver owns scenario-specific Rust execution, authenticated Host adapters,
durable CAS, reservations, dispatch, partial writes and recovery. Scheme owns
higher-order Session/Workflow/Governor semantics; Go owns cloud lifecycle and
routing proposals. Neither a proposal nor a Lean receipt is a send permit.

* Composable interface

| Module | Responsibility | Existing mechanism reused |
|--------+----------------+---------------------------|
| Context | Original scope, deciding revisions, named profile requirements | Explicit caller-supplied typed data |
| Admission | Validate actual operation, schema, current source and error-free Cedar allow | BoundOperation, PolicySnapshot, Functional compilation, upstream validators |
| Consumption | Compose original-operation admission and effect-bound grant consumption | OperationLedger and AuthorityLedger |
| AuthorizationDelta | Prepare source-bound C4 revision, analyze gains/losses, compose conditional proofs | Exact operational Delta, policy/provenance changes, proof footprint |

Authorization uses flat =Except= composition. Each validation step returns either
a specific failure or evidence retained by the resulting =Receipt=. Transparent
=Prepared= constructors cannot bypass revalidation. Required checks must match
the profile's unique ordered names exactly; unknown, omitted, duplicate or
refused assessments fail closed.

The canonical operation ID comes from the original scope, independently of a
grant ID. Renewed approval cannot admit that ID again against the returned
operation ledger. This is a pure transition: failure exposes no partial updated
ledger. A caller can still pass an old ledger, forge source metadata or fail to
persist the result; preventing those actions is the Host transaction contract,
not a theorem established by this library.

* Binding and trust assumptions

The Host authenticates the original root/claim, operation identity, profile,
budget/history domains, schema identity, source cut and module/projection closure.
Nonempty strings are structural validation, not authentication. The supplied
schema identity must commit to the actual schema; a satisfied assessment is not
proof that external history, source freshness or budget storage is truthful.

Admission compares exact source modules and recompiles the captured root.
Delta reuse compares exact source modules, scope and both compiled policy sets.
This conservative whole-model binding also invalidates unrelated declaration
changes. It intentionally makes no incremental reuse or hash-performance claim.
The typed schema is retained and actual requests/entities are validated against
it. Changes to schema or facts require new bound analysis, not relabeling old
evidence with a new context string.

At final use the Host must serialize current scope/revisions, source identity,
original-operation consumption, grant use and the original reservation in a
durable transaction. Context equality here compares provided values; it does not
close a read-to-CAS race or prevent storage rollback. Unknown outcomes retain
their original reservation. Retries, partial writes and reconnects cannot obtain
new effect capacity merely by replacing a grant or operation identity.

* Proof composition

=admitted_actual_request_is_error_free= transports the existing compound receipt
to the actual bound effect/state. =admitted_context_is_current= and the profile
laws expose exactly what admission checked.

=ExactCoverage= retains the upstream theorem's well-formed-schema, successful
typed-query and UNSAT premises for every schema environment. The no-execution-gain
theorem retains request/entity validation and strong environment well-formedness
for both policy sets. =admitted_execution_preserves_delta= joins that theorem
with an actual admission receipt through explicit equality with the after-policy
set. Its conclusion is pointwise in one validated world. It proves neither
unchanging external facts nor atomic publication nor external exactly-once send.

Execution Delta means allow with no evaluation errors; it differs from decision
Delta, which can observe allow despite errors. Policy-body, provenance and proof
footprint changes remain separate outputs. Empty gain reports do not construct
=ExactCoverage=. Executable CVC5 analysis validates/replays witnesses; UNSAT is
still a solver result, not a newly imported kernel proof certificate.

* Validation

Run =just check-gateway= for module/contracts and axiom audit. Run
=CVC5=/absolute/path/to/cvc5 just check-gateway-delta= for solver-backed
loss-only restriction, gain-only unfreeze, equivalence and stale binding checks.
The existing =check-authorization-delta-proof= lane builds the contracts;
=check-delta= runs solver checks in the existing solver-enabled CI job.

The local audit used Lean 4.34.1 and CVC5 1.3.4 without changing dependency pins.
All 28 executable contract assertions passed, and eight exported laws were
audited for inherited axioms. Contracts cover actual-effect/state replacement, stale owner/fact/source context,
source/provenance mutation, unknown/missing/duplicate checks, operation replay
with renewed grants, missing/mismatched/exhausted authority and changed schema or
projection scope. Solver fixtures span both declared action environments.

During development, compilation exposed a Cedar =Effect= namespace collision,
non-decidable validation error equality and an unavailable Option helper. Those
failures were corrected using explicit generic parameters and proof-producing
validation combinators; no axiom, timeout or validator was weakened. Axiom audit
prints inherited Cedar native-decide dependencies separately from ordinary Lean
logical axioms. Full-repository CI and Weaver runtime admission are distinct
receipts and must not be inferred from these focused tests.
